# 云市场与插件授权安装待办

## 状态

本文档记录尚未实现的云市场、授权码安装和云市场购买安装能力，供后续协议设计与实施使用。

当前状态为“待设计、待实现”。本轮只记录问题和边界，不新增云平台接口、数据库结构、任务类型或前端行为。

## 当前实现

Core 当前只具备通用插件交付基础设施：

- `POST /ptadmin/addons/download` 接收调用方提供的 `source` 或 `url`，可选校验 SHA-256。
- `PackageDownloader` 只负责把本地文件或 HTTP(S) 资源写入任务 artifact，不判断商品、订单或授权权益。
- `Installer` 负责解包、manifest、文件清单、签名、资源同步和生命周期，不访问云市场。
- `ApplicationIdentity` 已提供稳定的应用实例 ID 和 RSA 密钥对，但尚未用于平台挑战、授权绑定或下载票据签名。
- 后台前端已有云市场页面和平台登录、目录、安装接口调用占位，但 Core 与开发宿主没有对应 HTTP 路由。
- 授权码安装入口当前只显示待接入提示，没有后端请求和任务编排。

因此，现有 `addon.download` 不能视为云市场下载，也不能证明当前应用实例拥有插件授权。

## 尚未实现的能力

### 云市场接口

- 平台账号登录、登出、会话刷新和当前用户查询。
- 云市场分类、商品、插件版本、价格、上下架状态和已购状态查询。
- 平台 API 基址、协议版本、超时、重试和错误码映射。

### 授权码安装

- 授权码合法性、插件编码、版本和有效期校验。
- 授权码与 `application_instance_id` 的绑定和重复兑换保护。
- 使用应用私钥完成平台挑战或请求签名。
- 根据有效授权签发短期下载票据。
- 安装成功后的激活记录、后续校验、撤销和实例迁移。

### 云市场购买安装

- 幂等创建订单、创建支付、查询订单和关闭订单。
- 免费插件领取与付费插件购买的统一权益结果。
- 支付完成后生成实例授权并签发下载票据。
- 购买、下载和安装任务之间的状态关联与失败恢复。
- 退款、撤销、订单关闭或授权失效后的处理策略。

## 模块边界

后续实现不应把平台账号、订单和支付逻辑继续堆入 `PTAdmin\Addon`。建议先按以下职责设计协议，最终命名可在实施前确认：

```text
PTAdmin\Cloud\Marketplace
    负责市场目录、商品版本和平台账号会话

PTAdmin\Cloud\Purchase
    负责订单、支付和权益确认

PTAdmin\Cloud\Authorization
    负责授权码、实例绑定、激活状态和授权迁移

PTAdmin\Cloud\Delivery
    负责短期下载票据、受控下载地址和 artifact 元数据

PTAdmin\Addon
    只负责下载后的包校验、安装、资源同步和生命周期
```

`Cloud` 可以依赖 Addon 的任务入口完成交付，Addon 不应反向依赖平台账号、订单或支付实现。这样本地插件安装仍可独立使用，云市场不可用也不会破坏已有插件的本地生命周期管理。

## 统一安装链路

授权码安装和购买安装应在取得授权后汇入同一条交付链路：

```text
确认商品和插件版本
→ 校验购买权益或授权码
→ 绑定当前 application_instance_id
→ 签发短期下载票据和预期 SHA-256
→ 创建 addon.download 任务
→ 校验 artifact 摘要、manifest、文件清单和签名
→ 创建 addon.install 或 addon.update 任务
→ 校验安装结果并记录实例授权状态
```

云平台不得直接绕过 `PackageDownloader`、`ManifestVerifier` 和 `Installer` 写入正式插件目录。

## 安全与数据边界

- 平台密码不得写入任务 payload、事件、日志或长期配置；后续需要明确短期会话或令牌的存储与撤销方式。
- 应用私钥不得离开 `ptadmin.json`，平台挑战只上传实例 ID、公钥、时间戳、随机数和签名结果。
- 下载票据必须短期有效、一次性或有限次使用，并绑定插件、版本、实例和 artifact 摘要。
- 下载客户端必须验证 TLS，限制重定向、响应大小、超时和允许访问的域名，不能接受平台返回的任意内网地址。
- 授权码、访问令牌、下载票据和支付信息必须进入任务脱敏规则，不能出现在 JSONL 事件和 Admin API 响应中。
- 订单创建、授权绑定、下载和安装均需要幂等键，页面重试不得产生重复订单或重复消耗授权码。
- 市场授权状态不能替代插件包签名；授权有效但包校验失败时仍必须拒绝安装。

## 待确认协议

实施前必须确认以下产品和平台协议：

1. 平台账号使用密码换取短期会话，还是使用浏览器授权回调。
2. 授权码绑定插件固定版本、版本范围，还是插件所有后续版本。
3. 一个授权允许绑定几个应用实例，以及实例重建后的迁移和撤销规则。
4. 免费插件是否仍生成授权记录，还是只签发匿名下载票据。
5. 支付成功与授权生成是否由订单查询确认，是否需要 webhook 或轮询。
6. 插件运行时是否需要周期性在线验权、离线宽限期多长，以及平台不可用时是否允许继续运行。
7. 下载成功但安装失败、安装成功但授权激活记录失败时如何补偿和重试。
8. 退款、封禁、下架和签名密钥撤销分别影响新下载、升级和已安装插件的哪些能力。

## 实施阶段

### 第一阶段：协议与客户端

- 固定云平台 API 版本、请求签名、统一错误码和响应结构。
- 定义平台会话、应用实例挑战和敏感字段存储规则。
- 增加可替换的 Cloud Client，测试使用假平台，不依赖真实线上接口。

### 第二阶段：授权与交付

- 实现授权码校验、实例绑定、授权状态存储和下载票据。
- 由 Delivery 把票据解析为受控下载请求，并复用 `addon.download`。
- 串联下载与安装任务，保留两个任务各自的事件和失败状态。

### 第三阶段：购买流程

- 实现订单创建、支付发起、订单查询、关闭订单和权益确认。
- 支付或免费领取成功后进入与授权码相同的 Delivery 流程。
- 增加订单、授权、下载任务和安装任务之间的可追踪关联。

### 第四阶段：后台前端

- 将现有云市场页面切换到正式 Admin Transport 和稳定 API。
- 完成平台登录、商品详情、授权码安装、购买支付、进度和错误恢复。
- “我的应用”同时展示本地安装状态和平台授权状态，不把二者合并为一个布尔值。

### 第五阶段：验证与文档

- Core 单元测试覆盖请求签名、授权绑定、幂等、脱敏、票据过期和平台错误映射。
- `ptadmin-dev` 使用假平台覆盖授权码安装、免费领取安装、付费订单确认、下载失败和安装回滚。
- 补充用户操作文档、平台接口协议、运维配置和授权迁移说明。

## 验收条件

- 授权码安装和购买安装都通过同一受控 Delivery 与 Addon 安装链路。
- 未授权、授权绑定其他实例、票据过期、摘要不符和包签名失败均在对应阶段明确拒绝。
- 重复提交不会重复扣款、重复兑换授权码或并发覆盖插件目录。
- 平台不可用不会影响本地插件列表、启停和卸载；是否影响已安装商业插件运行按已确认的离线策略执行。
- Admin API、任务事件和日志不暴露密码、令牌、授权码、下载票据或应用私钥。
- 云市场前端不再调用不存在的占位接口，授权、购买、下载和安装状态可以恢复和追踪。

## 历史实现参考

历史 `ptadmin-addon` 中的 `AddonApi`、`AddonLicenseService` 和 `CloudMarketPurchaseService` 只作为业务线索，不直接迁移。旧实现混合了静态 API、平台会话、授权文件和购买调用，后续必须按上述边界重新设计，并以当前应用身份、任务状态机和插件信任链为准。
